# Visual Completion

Use this module only for visual-style sparse inputs while generating the locked UI reference. Do not use it to reinterpret a style-rich UI screenshot, photograph, or finished mockup.

Required structural anchors: the bottom dock and all widget groups shown in the reference must remain clearly visible.

Create a finished, high-fidelity, contemporary UI design from the user's request and any provided reference. Treat this as design completion and visual refinement, not an unconstrained redesign.

Before generating, silently interpret the input at four levels:

1. Structural anchors: the page-level regions and persistent interface structures that define the design, including any visible dock, bottom bar, sidebar, top navigation, major panel, widget group, modal, primary content region, or other large compositional area.
2. Enrichable components: elements whose internal content, states, controls, data, imagery, iconography, and styling may be developed.
3. Open areas: places where supporting content or visual elements may be added to make the interface coherent, realistic, and compositionally complete.
4. Functional ownership: the single most appropriate component or region responsible for each major function, action, data set, status, navigation role, and visual focal point.

Preserve all clearly depicted structural anchors unless the user explicitly requests a structural redesign. Keep their approximate position, prominence, and spatial relationships. Do not remove, replace, merge, obscure, crop, or reinterpret persistent navigation such as a dock, bottom bar, sidebar, or top bar. A rough sketch or wireframe defines structure and intent, but its unfinished visual style does not need to be preserved.

Be creative within the preserved structure. Expand components with plausible internal layouts, icons, labels, imagery, data, metadata, controls, active and selected states, badges, indicators, previews, charts, thumbnails, avatars, or other contextual details when appropriate. Add supporting elements that a real finished product would naturally contain, but do not introduce unrelated product concepts or change the screen's primary purpose.

Maintain clear functional ownership across the interface. Each major function, primary action, data set, status, navigation role, and focal visual should have one canonical home. Do not reproduce the same function as multiple full-sized widgets, cards, panels, toolbars, or navigation regions.

If the same information is useful in more than one context, present it according to the scope of each location. Keep the complete version in its primary component, and use only a compact summary, indicator, shortcut, or contextual reference elsewhere. Do not duplicate the entire component.

Distinguish intentional repetition from accidental duplication. Repetition is appropriate when it represents a meaningful collection or system, such as a list, application dock, gallery, data series, set of peer widgets, repeated rows, or consistent navigation items. In these cases, repeated items should share a coherent component system while containing distinct content, states, or roles.

Do not clone, mirror, or repeat components merely to create symmetry, increase information density, or fill an open area. Do not add multiple modules that answer the same user need, display essentially the same information, or offer the same primary action under different labels.

Before introducing a new functional block, first consider whether the design can be completed by enriching an existing component, improving its internal hierarchy, adding a meaningful state, adjusting proportions, strengthening imagery, or refining the overall composition. Add a new block only when it has a distinct and contextually justified purpose.

If no reference is provided, infer a convincing screen structure and the supporting elements most appropriate to the requested product and scenario. If the input is sparse, do not simply enlarge a few elements or leave large empty areas. Develop enough meaningful content, component detail, and density variation to make the interface feel complete and actively used. Resolve open areas through compositionally appropriate content, imagery, hierarchy, or spacing rather than duplicated functionality.

The result should resemble a real, current-generation product interface rather than a wireframe, generic template, or speculative concept image. Use contemporary UI patterns and visual treatments that fit the product category, audience, platform, and context.

Create a clear reading path and distinct primary, secondary, and tertiary levels. Use carefully considered typography, controlled differences in font size and weight, precise alignment, coherent grouping, balanced proportions, a consistent spacing rhythm, and purposeful whitespace. Whitespace should improve hierarchy and focus without making the screen feel empty.

Use a cohesive and relatively restrained color system, but retain enough tonal variation, accent color, imagery, and surface contrast to avoid a flat or lifeless result. Build contrast through scale, typography, color, component dimensions, content density, borders, surfaces, and subtle light and shadow.

Apply visual effects selectively. Fine borders, soft elevation, subtle gradients, controlled transparency, layered surfaces, refined iconography, polished imagery, and nuanced material details may be used when they improve hierarchy, realism, or identity. Keep the overall composition controlled, but allow one or two well-judged visual focal points to give the design character.

Make each visual focal point distinct in purpose and treatment. Do not repeat the same hero graphic, decorative illustration, accent composition, oversized icon, glow treatment, or signature visual motif across unrelated regions. Reuse visual language for consistency, but do not duplicate focal content.

Make components feel precise, detailed, and internally coherent. Components belonging to the same design system should share styling rules, but their content and purpose should not feel copied and pasted. Use realistic content and meaningful UI states instead of repeated placeholders.

Render user-provided text exactly as written. When supporting copy or data is missing, create concise and plausible content consistent with the implied product. Avoid repeating the same labels, values, status messages, imagery, or sample content across different components unless the repetition is functionally necessary.

Resolve the whole canvas as a complete interface. Every region should have an intentional compositional role, and no important area should feel accidentally empty, unfinished, clipped, misaligned, or disconnected.

Before finalizing, silently review the complete screen for unnecessary duplication:

- Each major functional region should serve a distinct user need.
- Each primary action should have one clear canonical location.
- Each important data set or status should have one primary owner.
- Global navigation should not be recreated as local navigation.
- No two major cards, widgets, or panels should communicate essentially the same content.
- Repeated components should form an intentional collection or system, not appear as isolated copies.
- Repeated items within a collection should contain meaningfully distinct content or states.
- Decorative focal elements should not be cloned across unrelated areas.
- An open area should not be filled by duplicating an existing feature.
- Any unnecessary duplicate should be removed, consolidated, or converted into a smaller context-appropriate summary.

Keep the macro structure stable, enrich the component-level experience, and use visual-design freedom in typography, color, imagery, materials, depth, and detail. Maintain consistency through shared design rules rather than repeated content or duplicated modules.

The final result should feel realistic, polished, contemporary, visually engaging, thoughtfully designed, and compositionally complete without becoming repetitive, unnecessarily theatrical, or overdecorated.
